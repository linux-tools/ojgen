# 造数据细节与质量手册

造数据的价值不在"跑得出"，而在"测得准"。本手册是每个生成任务必须过一遍的检查清单。

## 1. 用例覆盖清单（强制）

每组数据生成后逐项自查：

- [ ] **样例**：必须包含与题面样例一致的用例（格式、多行结构、特殊字符完全一致）。
- [ ] **最小规模**：n = 0/1、空数组、空串、单字符、单节点图、区间退化为点。
- [ ] **最大规模**：每个维度的最大值；能卡掉错误复杂度（如 O(n²) 对 1e5）。
- [ ] **边界值**：0、负数、INT_MAX/INT_MIN、模数 ±1、恰好等于上限/下限。
- [ ] **构造型特殊数据**：
  - 数组：全相等、已升序、已降序、交替、只有一个不同元素；
  - 图：完全图、链、菊花图、二叉树、二分图、重边/自环（按题面允不允许）、不连通图（按题面允不允许）；
  - 字符串：全 a、回文、字典序边界、大小写混合、含空格（按题面允不允许）。
- [ ] **卡常数据**：最短路可用 `Graph.hack_spfa(n)` 卡 SPFA；卡 unordered_map 可构造模数冲突序列。
- [ ] **多行输出覆盖（硬性规则）**：若题面样例输出为**多行**，生成数据中必须存在输出为多行的用例（如 n > 1、多组答案）；不得所有用例输出都是单行。这是历史事故教训。
- [ ] **答案唯一性**：若答案不唯一（多解、浮点误差），必须用 Special Judge 而非精确比对。
- [ ] **随机性检查**：随机数据是否可能以极小概率违反约束（如随机生成"互不相同"必须去重而不是碰运气）。

## 2. 约束校验（validator）

数据必须满足题面声明的一切约束。推荐写一个独立 `validate.py` 逐文件校验：

```python
# 伪代码：读入一个用例，逐条断言题面约束
def check(path):
    n, m = map(int, open(path).read().split()[:2])
    assert 1 <= n <= 1e5 and 1 <= m <= 2e5
    # 图：无重边自环、连通性、边权范围……
```

- 图类题校验：节点编号 ∈ [1,n]、边数正确、无重边/自环（如题面要求）、树的连通性（并查集）。
- 找不到现成 validator 时，至少用题目标程跑一遍全部数据，确保不 RE、输出非空。

## 3. 答案生成与对拍

- **标程优先**：能跑标程就不要手写答案。手写答案与标程不一致是常见翻车点（尤其边界）。
- 标程也要测：先拿题面样例喂标程，输出与样例完全一致再生成全量数据。
- 用 CYaRon 对拍器验证标程与朴素解一致：

```python
Compare.program("std.exe", "brute.exe", input=input_io, std_program="std.exe")
Compare.output("1.out", "2.out", std="std.out")
```

- 多解/浮点题：用 `checker.cpp` 本地跑一遍所有用例（`checker.exe in.txt out.txt ans.txt`）。

## 4. 随机与确定性

- 必须可复现：生成器记录 seed（本框架 `Gen(..., seed=...)`，或命令行 `python gen.py --randseed=12345`），交付时把 seed 写进 `manifest.json`。
- 复现流程：换一台机器用同 seed 应产出**完全一致**的数据。
- 随机策略分层：小数据全随机；大数据一半随机一半构造；每个子任务单独控制范围（`subtask` 风格：i 越小范围越小）。

## 5. 文本与格式规范

- **换行统一 LF**：Windows 下 `print` 会输出 `\r\n`，判题机（Linux）可能因此 WA。本框架打包时强制转 LF；自己 `open()` 写文件时务必加 `newline="\n"`。
- **无行末多余空格**：`print(a, b)` 没问题，`print(a, b, end=" ")` 会留下尾空格；严格比对的平台会判 WA。
- **文件末尾换行**：每个 `.in/.out` 以换行结尾；拼接文件用例之间不要插空行。
- **浮点**：按题面精度格式化（`f"{x:.6f}"`）；避免 `-0.0`（判 `if x == 0: x = 0`）；避免科学计数法（`1e-7` → `0.0000001`）。
- **字符串**：含空格的串要用 `getline` 约定（题面写明）；不要生成题面字符集之外的字符（如题面"小写字母"就别出数字）；注意转义字符、不可见字符。
- **中文**：文件统一 UTF-8 编码（本框架默认）。老 OJ（POJ）GBK 时代题目避免用中文数据。

## 6. 生成效率

- 大数据（>1e5 行）用 PyPy 跑生成器；避免一行一次 `write`，先收集到 list 再 `"\n".join(lines)` 一次性写入。
- 图类大数据：用 `Graph.tree(n)` 等批量构造，不要逐边 `randint` 判重（会退化）。
- 生成 1e6 级数据时关掉逐用例 print（本框架 `verbose=False` 可省时间）。

## 7. 常见坑速查

| 坑 | 规避 |
| --- | --- |
| `randint(1, n)` 闭区间，`range` 左闭右开 | 生成前核对上下界 |
| CYaRon 图节点从 1 编号，题面从 0 编号 | 统一按题面转换 |
| `Graph.graph` 的 `self_loop` / `repeated_edges` | 显式传参，默认值按题面核对 |
| `Vector.random` 一维结果是 `[[x], [y]]` | `sum(output, [])` 展平 |
| 随机"互不相同"用 while 重试 | 大 n 下概率爆炸，改用 shuffle/采样 |
| 标程读入用 `int()` 但数据是 `3.0` | 整数数据严禁写成浮点形式 |
| `input_write` 不换行导致两行粘连 | 一行结束时必须用 `input_writeln` |
| LeetCode 数据用 `str(list)` | 必须 `json.dumps`（`str([1,2])` 有空格，且字符串引号不对） |
| 生成器在 Windows 运行、判题机 Linux | 路径分隔符、换行符、`os.system` 都按 Linux 习惯输出 |

## 8. 交付前终检

1. 样例在生成数据中的那份与题面逐字节一致；
2. `validate.py`（或标程）通过全部用例；
3. 每个文件 LF 结尾、末尾有换行、无尾随空格；
4. `manifest.json` 记录平台、题号、用例数、seed、生成时间；
5. 特殊 judge 题已附 `checker.cpp` 并在本地验证 AC/WA 行为正确。
